# 登录密码校验（SHA-256 双层链路）

## 算法

```
第一层（浏览器）  L1 = sha256( usercode + "_" + 明文密码 )
第二层（服务端）  L2 = sha256( usercode + "_" + L1 + "_" + salt )
比对对象          ucsdb.account.pwd（64 位十六进制，库内存大写）
```

三层材料：

| 材料 | 来源 | 说明 |
|---|---|---|
| `usercode` | 用户输入 | 首尾空白会被去掉 |
| 明文密码 | 用户输入 | **不出浏览器** |
| `salt` | `ucsdb.account.salt` | 每账户一行一个，6 位数字 |

## 已验证的样例

```text
usercode = yjr    password = abcd123456    salt = 213926

L1 = 1d12f00cfa8a39ee3751a2df8eab50924cc064615113cb28f869cc057b6a5a0d
L2 = cff35b11d34d25bc445b0b0aebb5bbd60a428063156e9ddfc35cc1821a84ccb4
库内 pwd = CFF35B11D34D25BC445B0B0AEBB5BBD60A428063156E9DDFC35CC1821A84CCB4  → MATCH
```

## 实现位置

| 端 | 文件 | 作用 |
|---|---|---|
| 前端 | `frontend/src/utils/sha256.js` | `stage1Hash()` 计算 L1；WebCrypto 优先，非安全上下文回退纯 JS |
| 前端 | `frontend/src/views/Login.vue` | 提交 `{usercode, password: L1}` |
| 后端 | `backend/app/core/auth.py` | `stage2_hash()` 算 L2，`verify_password()` 常量时间比对 |

## 关键约定

1. **只认 `dbsplitcode='1'`** 的主库账户；`status=1` 为启用，停用账户直接拒绝。
2. **`memo` 字段不再参与校验**。历史实现用 `memo AS pwd` 做明文比对，已废弃。
3. **重复 usercode**：库内 `uk_account_entid_usercode` 是唯一索引，但历史上存在少量同 usercode 记录（如 `entid` 不同）。后端会取出全部候选逐一验证，任一条匹配即通过，避免 `fetch_one` 随机命中导致登录不稳定。
4. **向后兼容**：后端也能接受明文密码（`password` 不是 64 位 hex 时服务端自行算 L1），方便 curl 调试；前端始终传 L1。
5. **大小写无关**：库内 pwd 为大写，比对前统一转小写，使用 `hmac.compare_digest` 防时序攻击。
6. **失败不区分原因**：用户不存在、密码错、账户停用，一律返回 `401 用户名或密码错误`，避免账户枚举。

## 运维工具

```bash
cd backend

# 查看账户状态（只显示哈希前 16 位）
python tools/pwd_tool.py show yjr

# 校验某密码能否登录（不写库）
python tools/pwd_tool.py check yjr abcd123456 -v

# 修改密码（保留原 salt）
python tools/pwd_tool.py set yjr 新密码

# 修改密码并换 salt
python tools/pwd_tool.py set yjr 新密码 --new-salt

# 全量审计：salt 缺失 / pwd 非 64 位 / 停用 / 重复账户
python tools/pwd_tool.py audit
```

## 前端 401 处理

`api/index.js` 的响应拦截器原本把所有 401 都当成"会话过期"并跳登录页，导致登录页输错密码时提示错误。现在按 URL 区分：`/auth/login` 的 401 显示后端真实文案（用户名或密码错误），其余接口仍走会话过期逻辑。

# 菜单权限与个人收藏夹方案

## 一、需求

1. 首页不再固定打开"集装箱跟踪"，改为空白首页（`HomeDashboard`），首页可展示个人收藏的菜单。
2. 每个人可按自己的情况收藏菜单（收藏夹），并可从左侧快速进入。
3. 收藏夹提供"可配置"入口，批量勾选常用菜单（类似截图"添加常用菜单配置"）。
4. 标签栏增加"标签选项"下拉：`关闭所有`、`关闭其他`；并增加星标快捷入口打开收藏配置。
5. 增加菜单相关后端表，按权限配置每个人的菜单权限，模型为：员工 → 角色 → 菜单（员工-角色、角色-菜单关联）。

## 二、权限模型

```
员工(ucsdb.account.usercode)
   └─ 员工-角色 ops_user_role
        └─ 角色 ops_role
             └─ 角色-菜单 ops_role_menu
                  └─ 菜单 ops_menu
```

- **未分配任何角色**的员工：默认可见全部菜单（兼容升级，避免老用户升级后无菜单可用）。
- **分配了角色**的员工：可见其所有角色的菜单并集；若任一角色 `is_admin=1`，可见全部菜单。
- **收藏夹**只能收藏当前用户有权限的菜单；权限变更后，已无权限的收藏项自动隐藏（不删数据）。
- 员工账号直接复用 `ucsdb.account`，不另建员工表。

## 三、表结构（bidb，用户手工执行）

脚本：`deploy/sql/bidb_menu_permission.sql`

| 表 | 说明 |
|---|---|
| `bidb.ops_menu` | 菜单定义：编码(=路由)、中英文名、路径、图标、分组、排序、状态 |
| `bidb.ops_role` | 角色：编码、名称、`is_admin` 超管标记、状态 |
| `bidb.ops_user_role` | 员工-角色关联（唯一键 usercode+role_code） |
| `bidb.ops_role_menu` | 角色-菜单授权（唯一键 role_code+menu_code） |
| `bidb.ops_user_favorite` | 个人收藏（唯一键 usercode+menu_code，含排序） |

脚本内含初始化数据：21 条现有菜单 + 首页、两个默认角色（ADMIN 超管、STAFF 普通员工）。重复执行不会插入重复数据。

## 四、后端接口

路由前缀 `/api/menu`：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/my-menus` | 当前用户有权限的菜单（分组结构） |
| GET | `/my-favorites` | 我的收藏 |
| POST | `/my-favorites` | 批量保存收藏（`menu_codes` 全量替换） |
| GET | `/roles` | 角色列表（含菜单数/员工数） |
| POST | `/roles` | 新增角色 |
| PUT | `/roles/{id}` | 修改角色 |
| DELETE | `/roles/{id}` | 删除角色（级联清理授权与员工关联） |
| GET | `/role-menus?role_code=` | 角色的菜单编码列表 |
| POST | `/role-menus` | 保存角色菜单授权 |
| GET | `/user-roles?usercode=` | 员工的角色列表 |
| POST | `/user-roles` | 给员工分配角色 |
| GET | `/users?keyword=&page=` | 搜索员工（来自 ucsdb.account） |

GET 沿用 `?q=<JSON>` 传参约定；写操作用 JSON body；全部走 JWT 鉴权。配置类接口后端会二次校验管理员角色。

## 六、部署注意事项

1. **必须先执行** `deploy/sql/bidb_menu_permission.sql`，否则菜单/收藏/权限页面会报 503。
2. 执行脚本后：未分配角色的员工默认看到全部菜单，行为与改造前一致；需要精细化控制时，在"系统管理 → 菜单权限配置"里建角色、勾菜单、分配给员工。
3. 超管角色（ADMIN）默认拥有全部菜单且不可修改授权；如需给某人全部权限，直接分配 ADMIN 角色即可。
4. 首页标签固定不可关闭，收藏夹配置在标签栏"标签选项 → 配置常用菜单"或首页齿轮进入。
5. 标签栏星标为收藏切换按钮：点击把当前页面加入收藏（星标变黄），再点取消收藏；首页不参与收藏。

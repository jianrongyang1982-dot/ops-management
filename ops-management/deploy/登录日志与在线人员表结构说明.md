# 登录日志 / 在线人员 表结构说明

## 变更说明

按需求，**不再沿用 ERP 的 `logdb.loginlog`**，改为本系统在 `bidb` 库自建两张表：

| 表 | 用途 |
|---|---|
| `bidb.ops_login_log` | 登录日志：每一次登录尝试（成功 / 失败）都记录 |
| `bidb.ops_online_user` | 在线人员：每个账号一条，登录时 upsert，后台退出时置 `status=0` |

岗位名称 / 部门名称在登录时从 `ucsdb` 字典表取快照写入在线表，页面查询时**只读本表**，不跨库联表。

## 需要你手工执行的 SQL

脚本文件：`deploy/sql/bidb_login_online.sql`

用有 `bidb` 库建表权限的账号执行（脚本中所有表都带 `bidb.` 前缀，与当前连接库无关）：

```bash
mysql -h<host> -P<port> -u<user> -p < deploy/sql/bidb_login_online.sql
```

### 表 1：登录日志 `bidb.ops_login_log`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT AUTO_INCREMENT | 主键 |
| `usercode` | VARCHAR(50) | 账号 |
| `username` | VARCHAR(200) | 姓名 |
| `terminal` | VARCHAR(20) | 终端平台，默认 `PC-WEB` |
| `product` | VARCHAR(50) | 产品，默认 `web` |
| `device` | VARCHAR(255) | 设备信息 |
| `success` | TINYINT | 1=成功，0=失败 |
| `client_ip` | VARCHAR(50) | 客户端 IP |
| `cost_ms` | INT | 消耗时间（毫秒） |
| `login_time` | DATETIME | 登录时间 |
| `remark` | VARCHAR(255) | 备注（失败原因等） |
| `create_time` | DATETIME | 写入时间 |

索引：`idx_usercode`、`idx_login_time`、`idx_user_time(usercode, login_time)`、`idx_success_time(success, login_time)`

### 表 2：在线人员 `bidb.ops_online_user`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | BIGINT AUTO_INCREMENT | 主键 |
| `usercode` | VARCHAR(50) | 账号（**唯一键**） |
| `username` | VARCHAR(200) | 姓名 |
| `terminal` | VARCHAR(20) | 终端平台 |
| `product` | VARCHAR(50) | 产品 |
| `postname` | VARCHAR(200) | 岗位名称（登录时快照） |
| `deptname` | VARCHAR(200) | 部门名称（登录时快照） |
| `client_ip` | VARCHAR(50) | 客户端 IP |
| `device` | VARCHAR(255) | 设备信息 |
| `login_time` | DATETIME | 登录时间 |
| `last_active_time` | DATETIME | 最后活跃时间 |
| `status` | TINYINT | 1=在线，0=已退出 |
| `logout_time` | DATETIME | 退出时间 |
| `logout_reason` | VARCHAR(100) | 退出原因 |
| `create_time` | DATETIME | 首次登录时间 |
| `update_time` | DATETIME | 更新时间（自动更新） |

索引：`uk_usercode(usercode)` 唯一、`idx_status_login(status, login_time)`、`idx_active(last_active_time)`

## 代码侧的对应改动

- `backend/app/services/system_service.py`
  - 日志写入 → `bidb.ops_login_log`；登录成功时 upsert `bidb.ops_online_user`
  - 日志查询 → 只读 `bidb.ops_login_log`
  - 在线查询 → 只读 `bidb.ops_online_user`（`status=1` + 时间窗口）
  - 后台退出 → `UPDATE ... SET status=0, logout_time=NOW()`
- `backend/app/routers/auth.py`：登录成功 / 失败都写入新日志表，成功时同步在线表
- 前端页面无需改动：返回给前端的字段名保持一致

## 注意事项

1. **建表前登录仍然可用**：日志写入有容错，表不存在只会记 warning，不影响登录主流程；但日志和在线列表为空。
2. **旧的 `ipcmdb.ops_online_kick` 表已不再使用**，保留无害，可自行删除。
3. **在线状态是"本系统登录"的口径**：只有从本系统登录才会写入在线表；ERP 原生登录不会出现在列表里（这与之前沿用 `logdb.loginlog` 的行为不同，符合"不沿用原表"的要求）。
4. **后台退出**只改本系统在线表的 `status`，不影响 ERP 会话。
5. 同一账号重复登录会 **upsert 覆盖**（更新 IP、终端、岗位部门快照，重置登录时间），所以在线列表每个账号只有一行。
